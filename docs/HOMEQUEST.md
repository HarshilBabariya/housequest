# HomeQuest — the complete reference

Single source of truth for the product, the engineering handoff and the working context of the project. Updated with every release zip.

## 1. What HomeQuest is
A gamified household-expense manager for Android, built for Harshil (GitHub `HarshilBabariya/housequest`). Members of one household log spending on one phone, split it in groups, keep budgets, and earn points that unlock themes, avatar looks and features. Everything is local-first (Room + DataStore); the APK is produced by the repo's GitHub Actions workflow — the project has never been compiled on the authoring side, so every release is statically reviewed and then verified through the Actions build and on-device testing.

## 2. Working agreements (project memory)
- Deliverable is an installable build, not code: each release is handed over as a zip to push to `main`; the workflow in `.github/workflows/build-apk.yml` uploads `app-full-debug.apk` and `app-lite-debug.apk` (see Build flavours).
- Follow the coding standard and structure already in the project; no dead code, unused files or duplicated code; minimal comments.
- Every handover updates this document and the README version history in the same pass.
- Fixes are verified in a fresh review pass (not the session that wrote them) before a zip is handed over, and the user's screenshots/bug reports drive the next iteration.
- Known boundary: cross-device access for a member with the same mobile number needs a sync backend (e.g. Firebase phone auth + Firestore); it is intentionally out of scope and the app says so on the Family screen.
- Avatars are 2D Compose canvas art; the 3D-clay reference look was approximated (soft shading, circle frame), not replicated.
- Design references the user shared: a dark "cash-flow" style home with a centre **+** bottom bar, list-style add-transaction form with payment modes, playful mood-driven avatar.

## 3. Features
### Look & feel
- Adaptive launcher icon: coral-to-pink gradient, a large white house with pink door and windows filling the safe zone, gold star coin on the roof; round, squircle and Android 13+ themed (monochrome) variants are all supported.
- Material 3 throughout; each of the seven shop themes and nine festival themes defines its own surface, card and chip colours so the whole UI (not just the accent) changes when you apply one. **Glass** (600 pts) puts frosted, translucent cards and bars over a glowing three-colour gradient backdrop, in light and dark; the New Year Gold festival theme uses the same glass look.
- Icons are Material *Rounded* throughout (every `Icons.Filled` / `AutoMirrored.Filled` use was moved to the Rounded set): tab bar, stat tiles (sun, trend up/down, handshake, the top category's own icon), and every Me-tab row sits in a tinted icon tile instead of an emoji.
- Bottom navigation: four tabs (Home, Expenses, Groups, Me) on a rounded bar with a notch that cradles a raised, glossy 3D **+** button (gradient, highlight, coloured shadow, press-to-squish). The strip above the bar around the button is transparent — lists scroll underneath it instead of stopping at an empty band. The selected tab is shown only by colour — its icon switches to the filled version and icon and label turn the primary colour; there is no background pill.
- Every text that can overflow is clipped with an ellipsis on one line; nothing wraps into a second line unexpectedly. The exception is the category grid, whose labels wrap onto two centred lines.
- Three languages — English, हिन्दी (Hindi) and ગુજરાતી (Gujarati) — switchable from onboarding or Me → Language; dates, badge names, reward names, mood lines and notifications all follow the chosen language.

### First launch & accounts
- A three-step onboarding (You → Money → PIN) asks for your language, name and mobile number (required, 10+ digits), currency and optional budget, then lets you create a 4-digit PIN or skip it. The PIN step fits on one screen (the avatar shrinks, keypad centred, Skip pinned at the bottom) — it no longer scrolls; only on very short screens (under 560dp for the step) does it fall back to scrolling so Skip stays reachable. You become the household owner and start at Level 1 (Rookie). A daily "Log today's expenses" reminder at 20:30 is created for you.
- Every family member is an account: name, relation, mobile number (required), avatar and an optional 4-digit PIN. Weak PINs (1111, 1234…) are rejected and the PIN is confirmed twice.
- **Local-only**: all data lives in this phone's database. A member installing the app on another phone starts with an empty ledger — the number only identifies the profile on this device. Cloud sync is not part of this release (the Family screen says so).
- Member picker: after Log out you always land on the picker, even with a single profile; members with a PIN get a keypad. The PIN screen scrolls on small phones so the keypad is never cut off.
- App lock (Me → Security): switching it on creates a PIN on the spot if you don't have one, then asks for it every time the app opens.
- Log out / switch from the Me tab returns to the picker — also after switching to a member without a PIN (1.5.0 fix). Expenses, budgets and points are shared by the whole household — only avatar and greeting are per member.

Seven actions: Wave, Jump (squash and stretch), Spin, Dance (arms and hips), Wink (one eye + sparkle), Cheer (both arms up + confetti ring), Laugh (happy-closed eyes, open mouth, giggle shake). Static everywhere else (lists, chips, Me header).

Home picks the mood from budget progress, streak, days since your last log, time of day and day of month; the studio lets you preview all ten.

- New family members get a randomised look; those parts are free so households look varied from day one.

### Streaks
- Home has a **streak card**: an animated flame with the current streak, the last 7 days as flame dots, the next milestone, and whether today is "Safe for today ✅" or needs a log before midnight. "Start a streak" when there is none.
- The streak shown everywhere (Home pill and card, Me header, weekly share card, avatar mood) is the *current* streak: it drops to 0 once a day has been missed, instead of showing the last streak until the next log.
- Milestones at 3, 7, 14, 21, 30, 50, 75, 100, 150, 200 and 365 days, then every 100 days, open a full-screen celebration with a big flame, fireworks and a fire whoosh, plus a milestone notification.
- **Streak in danger**: at 21:30, if you logged yesterday but not today and the streak is 2+ days, a notification ("Your 12-day streak is in danger 😱", "Moye moye moment loading…") with a sad-trombone sound reminds you to log one expense.
- Level-ups now also open a full-screen celebration (star badge, confetti, air horn) instead of a toast.

### Sounds

### Home dashboard
- Header (compact): your animated avatar (tap for Me), name, a points · streak pill (tap for Rewards), a microphone button for voice entry, (the pill shows ⭐ points · 🔥 streak; the level lives on the bar below), then a labelled XP bar — "Level 6 · Accountant" on the left, "66 XP to Level 7" on the right, gradient fill — that also opens Rewards.
- All month/week figures follow the real calendar: the app re-evaluates "this month" at midnight (see `Dates.days()` in the handoff), so a month boundary never shows last month's totals.
- Cash-flow card: budget ring, spent this month, amount left / over.
- Stat tiles: Today (tap to add), vs last month, Group balance (tap to open Groups), Top category.
- **Month so far**: projected month-end spend ("on pace to spend", based on spending up to today — future-dated entries don't inflate it) with a cumulative area chart for the month and, when a budget is set, a dashed budget-pace line.
- **Last 7 days**: week total and daily average above gradient bars; today's bar is highlighted with its amount.
- **Forecast**: when a monthly budget is set, the Month-so-far card says in plain words where you are heading — "At this pace you'll overspend by ₹4,200, crossing the budget around 24 Nov", "On track: about ₹3,100 to spare", or "Already ₹800 over budget". The crossing day is today + (budget − spent) ÷ average daily spend so far.
- **Weekly summary card**: the Share action on "Last 7 days" renders a 1080×1350 image in the theme colours (week total, ▲/▼ vs the previous 7 days, top three categories with bars, who paid when more than one member did, streak and points) and opens the share sheet — made for the family WhatsApp group.
- **Payments to review**: when auto-capture has drafts waiting, a card under the header says how many and opens the review list.
- **Charts are tappable**: tap any bar to highlight it and show its amount; tap (or drag across) the month area chart for a bubble with that day's date and running total; tap a donut slice to enlarge it and show the category, amount and share in the centre (tap again or tap outside to reset). The same applies on Insights.
- Category donut, "Who paid this month", "Upcoming bills" (next three) and recent transactions with "See all".
- "Insights" shortcut appears once the Advanced Insights feature is unlocked.

### Insights (Advanced Insights unlock)
- **Week / Month / Year** tabs and a `‹ period ›` navigator with the transaction count; you can page back through any past week, month or year (not into the future).
- Spending hero: total for the period, ▲/▼ % vs the previous period, daily average, number of entries and the biggest expense.
- One-line insight (which category took the biggest share, or "nice and quiet" when nothing was spent).
- Spending trend: daily area chart for a month; bars per day for a week and per month for a year, with the current (or busiest) bar highlighted and labelled.
- Categories: donut plus a ranked list with share bars and ▲/▼ change vs the previous period per category.
- Payment modes: a split bar (Cash green, UPI violet, Card orange, Bank blue) with % and amounts; Who paid (when more than one member paid).

### Expenses & the add-transaction form
- The list opens with This month / vs last month tiles, a search field and category chips; entries are grouped by day with subtotals and show category · payer · payment mode. The top bar has two tinted tile buttons (`TopBarAction`): a calendar icon (the same `CalendarMonth` glyph as the other calendar entry points) that opens the Calendar and a tune icon for Categories.
- **Calendar** (Expenses → calendar icon, or Me → Views → Calendar): a month grid (first day of week follows the phone's locale) with each day's total; with a monthly budget set, days are green when within the average daily budget (monthly budget ÷ days in month) and red when over, and the footer shows that daily figure and a legend. Month arrows and a month dropdown (last 12 months); future days are greyed and not tappable. Tap a day to list its expenses underneath and tap one to edit it.
- Add transaction (centre **+** or Today tile): a "Say it or type it" voice banner, an amount hero, a title field, a Date row (date picker) with **Yesterday / Today / Tomorrow** quick chips and a Category row (sheet), then an inline card with **Paid by** member chips and the four **payment-mode** tiles — no sheet needed for either; a "Split with a group" row (sheet) and a note under "Other details". Group splits (equal or custom) appear inline when a group is chosen.
- Form sheets (new reminder, category, group, member, budget limit) close only with the X button or a tap outside — dragging while scrolling their content no longer dismisses them.
- **Credits** (cashback, refunds, money received): the add form has an *Expense | Credit* switch. A credit is stored as a negative amount, so it is automatically subtracted everywhere totals are summed — month and day totals, budgets, category and payer totals, Insights, Calendar, the weekly card, PDF and CSV. It shows as **+₹50** everywhere — green in lists, and a day, week or month whose net is negative (more credits than spends) shows its total as +₹… too, including Calendar cells and the PDF. Trend charts and budget rings treat a net-negative day or month as zero. With Credit selected the title reads *Add credit* and the button *Save credit*. Credits can't be split with a group (the group row and split card hide; a group already picked comes back if you switch to Expense), earn no logging points, don't trigger budget alerts and are ignored by badges (a credit said by voice still counts toward the *Say it out loud* badge); charts and "who paid" only show categories and members whose net total is above zero, and their percentages, donut centre and bars use the sum of what's shown, so they always add up to 100%. A month counts as under budget when it had at least one spend and its net total is within the budget. Voice entry marks a credit only when you say cashback, refund, refunded, credited, mila/मिला/मिले, रिफंड or કેશબેક/રિફંડ/મળ્યા ("credit card" stays a card payment); each new voice phrase sets Expense/Credit afresh. CSV import accepts negative amounts as credits (ASCII `-` or the `−` sign).
- **Payment modes**: Cash, UPI, Card, Bank (labelled "Bank" so the tile never truncates) — stored per expense and included in the CSV export. The Yesterday / Today / Tomorrow chips share the row equally and use the smaller label style so no label is cut off.
- **Voice entry**: tap the banner or the Home microphone, say e.g. "250 groceries by UPI" or "paid 120 for pani puri cash"; the amount, category (built-in keywords in English/Hindi/Gujarati words such as sabzi, kiraya, dawa, plus your custom category names), payment mode and title are filled in for you to review and save. The **Note** is filled too: say "note …" (or नोट / નોંધ) and everything after it becomes the note; otherwise the whole sentence you said is kept as the note. A typed note is never overwritten; a note that came from an earlier voice capture is replaced by the new one. "note" only counts as the marker when a word comes before and after it, and not after ka/ke/ki/no/ni/na, so "500 ka note" or "200 stationery notes" parse normally. Uses the phone's speech recogniser in the app language.
- The category sheet's labels wrap onto two centred lines instead of being cut at the tile edges, so long names such as "Rent & Home" or "Vegetables & fruits" and the Hindi/Gujarati labels read in full.
- **Custom categories** (Expenses → tune icon, or Me → Categories): add your own with a name, one of 26 icons and 40 preset colours plus a **custom colour** hue slider; built-in categories can be recoloured/re-iconed; deleting a custom category moves its expenses to Other.
- Titles, notes, names and reminder titles are saved with a capital first letter; text fields default to sentence capitalisation.
- Tap any expense to edit or delete it. Every new expense earns points (see Rewards).

### Household money (Me → Household money)
- **Kirana khata**: one card per shop with what you owe. In a shop's sheet, *Bought on credit* adds to the khata (with a note such as "atta, oil"); *Paid* records a payment with a payment mode and also logs an expense under Groceries titled "<shop> khata", so spending counts when you settle the shop, not twice. Credit entries can be deleted; the top card shows the total due across shops.
- **Milk, maid and services**: presets for milk, newspaper, water can (per unit) and maid, cook, driver (monthly), or your own. Per-unit services have a rate and units per day; monthly ones have a salary and an optional deduction per leave. Each service opens a month grid: per-unit days show the quantity (tap a day, then − / + in half steps; changed days are tinted), monthly days toggle ✓ present / ✕ leave. The bill line spells out the maths so far ("28.5 units × ₹60 = ₹1,710", "₹3,000 − 2 leaves × ₹100 = ₹2,800"). *Mark paid* pays the **full month** — the remaining days count at the usual quantity, shown as a separate line when it differs — records the month (a second tap can't pay it twice) and logs the expense in the service's category (maid, cook and other presets go to Other, milk to Groceries). Services count from the 1st of the month they were added, so you can back-fill earlier days. Past months can be browsed and paid.
- **Gold and chit funds**: a savings value card (gold at today's rate + instalments paid into chits whose prize hasn't been taken). Gold items have a label, grams, karat (24/22/18) and price paid; value = grams × 24K rate × karat ÷ 24, with ▲/▼ vs the price paid. The 24K rate per gram is set by you (the app is offline). Chits track monthly instalment, number of months and start month; *Paid this month* advances the instalment count, *Took the prize* records the amount received; the card shows progress and the next due month. Gold and chits are savings, not expenses — nothing is logged to the ledger. After a chit prize is taken the chit no longer counts toward the savings value. A full net-worth view (subtracting khata dues and loans, adding other assets) is not built yet.
- **Auto-capture payments** (full build only — the lite build leaves it out so it can be installed from WhatsApp or a file manager): after you grant notification access (the screen links to the system setting and shows whether it's on), HomeQuest reads payment notifications from GPay, PhonePe, Paytm, BHIM, CRED, Amazon Pay, YONO SBI, HDFC, iMobile, Axis, Kotak and the SMS apps (so bank SMS are covered without the SMS permission). Money in and money out with an amount become **drafts**: "paid you"/"sent you" is incoming; otherwise any debit word ("paid", "sent", "debited", "spent", …) makes it a spend — so "debited from your a/c and credited to Zomato" is a spend; only with no debit word do "credited", "received", refund or cashback make it incoming. Incoming drafts are credits shown in green with the sender as payee. OTPs, requests, pending, initiated, failed/declined, reversed, "due", "will be debited/credited/refunded", card-bill "payment received"/"received your payment", salary and interest alerts are ignored. A draft with the same amount within 10 minutes of another draft or an expense you just logged is dropped as a duplicate. Each draft shows amount, payee, source app and time with **Add** (one tap: the notification's date, UPI, payee as title, category guessed from the payee with the voice keywords), **Edit** (opens the add form pre-filled with amount, payee, guessed category and the notification's date; saving removes the draft) or ✕. A "Payment spotted" (or "Money in" for credits) notification appears for each new draft (follows the reminders notification toggle). Only amount, the other party, source app and time are stored — on the phone and in the normal Android backup; nothing is sent anywhere. On Android 13+ a sideloaded APK shows notification access as a *Restricted setting*; the Capture screen explains the App info → ⋮ → *Allow restricted settings* step and links to App info.

### Budgets & alerts
- Budgets screen: a hero card with the budget ring, spent / left this month and a "Set monthly budget" button; each category is a card with icon, name and progress bar on the left and the spent amount (with "of limit") centred next to the chevron — tap it to set or remove a limit in a sheet with quick-amount chips.
- Push notifications when a budget crosses 80% and 100% (can be switched off in Me → Notifications).
- Finishing a month under the overall budget earns +100 points and the Budget Boss badge.

### Groups & splitting
- Create groups (home, trip, party…) from your family members with an emoji — pick one of eight, or tap **+** to type/paste any emoji as a custom icon.
- Add an expense to a group and split it equally among chosen members or with custom amounts; the form shows live per-person shares and whether custom amounts add up.
- Group page shows total shared, who owes whom, a minimal "settle up" plan, and all shared expenses. "Mark paid" records a settlement and earns points.
- Share button sends a localised text summary of balances to WhatsApp, SMS, email, etc.

### Family members
- Add partner, kids, parents, roommates or friends with a relation label; each has their own avatar (tap to open the studio for them).
- Male/female per member; new members join as "from now on" or can be added to every existing group with past equal splits recomputed to include them (a choice sheet appears when groups exist).
- Removing a member who is part of shared expenses asks whether to re-split those past expenses between the remaining members or keep the old records; their own expenses and splits are then removed.

### Avatar studio
- Skin tone (6), hair colour (7), face shape (5) and beard (6, male only), always free.
- Hair (16), outfits (18) and accessories (13): short/buzz/long/curly/side part/pixie hair, tee/shirt/polo and no accessory are free; the rest unlock with points directly from the studio.
- Live preview on your own avatar (tap it for a random action), a row of seven action chips (Wave, Jump, Spin, Dance, Wink, Cheer, Laugh), a chip for each of the ten moods and Auto. The hero area is compact so more of the wardrobe is visible.

### Rewards & gamification
**Earning points**
- +10 per expense logged, +5 for the first log of the day, +2 per streak day (max +20)
- +30 create a group, +15 settle a balance, +20 add a family member
- +100 finish a month under budget
- Bonus points for every badge earned

**Levels** — XP-based (Rookie → Saver → Planner → Tracker → Strategist → Accountant → Treasurer → Guardian → Master → Legend). Level-ups open a full-screen celebration (star badge, confetti, air horn) and post a notification.

**Badges (33, easy and hard)** — bonus points total 6,130, more than the whole shop (≈6,650 pts) once logging points are added. Rewards shows the first eight (earned first, then closest to completion) in a row with staggered pop-in and a pulsing emblem on earned ones; "See all" opens the Badges page: a 3-column grid grouped into Earned / Easy / Hard with the points available in each group. Tap any badge for an animated detail card with a numbered "How to earn it" list.

Badge list: First step (1 expense), Getting serious (10), Century (100), Half a thousand (500), Week warrior / Month master / Iron streak / Legendary streak (7/30/60/100-day streaks), Early bird (log before 9 AM), Night owl (after 10 PM), Say it out loud (voice entry), Note taker (10 notes), Explorer (5 categories), Make it yours (custom category), Payment pro (all 4 modes), Big spender (one expense ≥ 10,000), Penny counter (20 under 100), Team player / Group guru (1/3 groups), Fair share / Settler (1/10 settlements), Family first / Full house (3/5 members), Bill planner (5 reminders), Budget boss / Budget hat-trick (1/3 months under budget), Stylist (outfit), Accessorized (3 accessories), New look (theme), Collector (5 paid unlocks), Polyglot (language switch), Rising star / Legend (level 5/10).

The Rewards hero card has a slow light sweep and a bobbing star; shop rows animate when the filter changes.

**Shop** — spend points on 7 colour themes (plus the 9 festival themes, claimable for free during their festival), avatar outfits, hair styles and accessories, and two features (Advanced Insights, CSV and PDF export). **Unlock everything with Pro** — a gold Pro card ("grab a points pack and unlock themes, looks and features faster"; a pack speeds unlocking up, it does not unlock the whole catalogue) (on Me and under the shop) opens a sheet with three plans: Starter ₹49 → 500 pts, Plus ₹99 → 1,200 pts, Pro ₹199 → 3,000 pts (marked *Best value*). Coming from Me opens Rewards with the sheet already up. Tapping a plan opens the system chooser with a `upi://pay` deep link to the configured UPI id (no SDK, no backend); the id itself is never shown in the app. If the UPI app returns `Status=SUCCESS` the points are credited at once; `FAILURE` shows an error; anything else (most apps return nothing useful) asks "Did the payment go through?" and credits on the user's word. Bought points go through the normal ledger (`purchase:<pack>`) and count toward levels. Points history is listed at the bottom of Rewards. Rewards opens from the Home pill or Me → Rewards.

### Reminders & bills
- The screen opens on a calm, animated **orbit**: a 30-day ring (12 o'clock is now, week ticks around it) on a slowly drifting aurora of the theme colours with twinkling stars and a sweeping comet. Each active reminder due within 30 days is a dot in its category colour at its due position; the next one pulses. The centre shows **Next up** — icon, title, a live countdown ("in 25 min", "Today, 8:30 PM", "Tomorrow, 9:00 AM", "In 6 days") and the amount — and opens it on tap. The footer sums the bills due in the next 30 days.
- Below it a compact timeline grouped into *Today & tomorrow*, *This week*, *Later* and *Paused*: one slim row per reminder with icon, title, amount, "due · schedule" and a small switch. Only bills due within a day turn red; a daily nudge is never shown as overdue. Edit and delete moved into the reminder sheet (tap a row; **Delete reminder** at the bottom, still with a confirmation). The *New reminder* button shrinks to an icon once you scroll.
- Repeat Once / Daily / Weekly (weekday) / Monthly (day of month) / Yearly (month + day); quick presets for rent, EMI, electricity, insurance, school fees and a daily nudge.

### Build status
The source was written and statically reviewed but **not compiled** in the authoring environment (no Android SDK / Maven access there). Expect a first build to surface only trivial issues such as a missing import or an API-signature mismatch for a Compose version. The `schemas/` directory for Room is generated on first build.

### CI
`.github/workflows/build-apk.yml` runs `assembleFullDebug` and `assembleLiteDebug` on Ubuntu 24.04 (pinned rather than `ubuntu-latest`, which moves to Ubuntu 26 from October 2026; actions are on their Node 24 majors: checkout/setup-java/setup-gradle/upload-artifact v5) with JDK 17 and the runner's preinstalled Android SDK (platform 35 / build-tools 35.0.0 installed via `sdkmanager`; the `setup-android` action is deliberately not used because it tries to install the retired `tools` package) and uploads two artifacts, `HomeQuest-full-debug-apk` and `HomeQuest-lite-debug-apk`. ### Build flavours
One dimension, `capture`, with the same `applicationId`, so the two replace each other in place and keep the data:

### Data model
- `members` — owner row seeded on first run (`isOwner = 1`); avatar fields stored inline (`skinTone`, `hairId`, `hairColor`, `outfitId`, `accessoryId`, `faceShape`, `beard`), plus `phone` and `pinHash` (`salt:sha256(salt:pin)`, see `util/Pin.kt`; PINs are exactly `Pin.LENGTH` = 4 digits, `Pin.isWeak` rejects repeats and sequences). `MemberEntity.avatar()` converts to `AvatarConfig`; `MemberEntity.hasPin` is derived. New members get a random avatar in `MemberRepository.add()`.
- Active account: `SettingsRepository.activeMemberId` (0 = nobody signed in). `MemberRepository.activeMember` is the flow screens use for "who am I"; `activeMemberId()` falls back to the owner. `MainViewModel.gate()` decides between onboarding, the lock screen (`ui/screens/profile/LockScreen.kt`) and the app; `sessionUnlocked` is in-memory so App lock re-prompts on every cold start.
- `categories` — `id` (built-ins keep the old enum names `GROCERIES`…`OTHER` so no expense rows had to be rewritten; custom ones are `custom_<millis>`), `name` (custom only; built-in names come from `BuiltInCategories.nameRes`), `icon` (key into `CategoryIcons`), `color` (ARGB), `sortOrder`, `builtIn`. `CategoryRepository.ensureDefaults()` seeds the built-ins at bootstrap (`INSERT OR IGNORE`). Deleting a custom category reassigns its expenses to `OTHER` and drops its budget. UI resolves ids with `List<Category>.byId()` / `Map.resolve(id)` and labels with `Category.label()` (composable) or `label(context)`.
- `expenses` — `category` is a category id string, `paymentMode` is `PaymentMode` (CASH/UPI/CARD/BANK, stored as text). `epochDay` (LocalDate.toEpochDay) is the only date used for grouping/queries; `createdAt` orders within a day. `paidByMemberId` cascades on member delete; `groupId` is set null on group delete.
- `expense_splits` — per-member share; present only for group expenses. Deleted with the expense.
- `groups`, `group_members` (junction), `settlements` — balances are computed in `GroupRepository.balances()` from expenses + splits + settlements; `SplitCalculator.settlements()` produces the minimal transfer list.
- `reminders` — `repeat` ONCE/DAILY/WEEKLY/MONTHLY/YEARLY with `weekday`, `dayOfMonth`, `month`, optional `amount` and `category`; `ReminderEntity.nextOccurrence()` (in `ReminderScheduler.kt`) computes the next fire time and clamps day-of-month to the month length.
- Household money (v7): `shops` + `shop_entries` (purchase or `payment` flag, cascade on shop delete), `services` (`billing` PER_UNIT/MONTHLY, `rate`, `defaultQty`, `leaveDeduction`, `category`, `startEpochDay`) + `service_days` (only days that differ from the default) + `service_bills` (one row per paid month), `gold`, `chits` (`paidMonths`, nullable `prizeAmount`), `payment_drafts` (amount, merchant, source, postedAt). `reminders.autoLog` turns a reminder into a recurring expense.
- `budgets` (per category id; the overall monthly budget lives in DataStore), `profile` (single row: points, lifetime XP, streak, last log day, last budget month checked, `voiceLogs`), `unlocks`, `earned_badges`, `points_ledger` (`reason` is a code from `LedgerReasons`, e.g. `badge:badge_century`, rendered by `reasonLabel()` in the current language).
- `members`, `expenses`, `groups` and `reminders` still carry an `isSample` column (always 0). It was used by the sample-data switch removed in 1.3.2; it stays because SQLite on minSdk 26 cannot `DROP COLUMN` and recreating four tables with foreign keys is not worth the migration risk. Nothing reads or writes it.

Insights figures and the dashboard's month-pace series are computed in memory from `ExpenseRepository.all` (the whole ledger is small enough), so period switching never needs a new query. The old `observeMonthCategoryTotals` SQL path was removed with the 6-month stacked chart in 1.5.0.

### CSV import / export & erase
- PDF (`Sharing.exportPdf` → `util/PdfReport`) is drawn with `android.graphics.pdf.PdfDocument` on A4 (595×842 pt): title, "N expenses · total", one line per category total, then a date / title / category / mode / paid by / amount table that paginates and repeats the header row on each page; cells are ellipsized to their column. File names are `homequest-expenses.csv|pdf` or `HomeQuest_<Month>_<yyyy>.csv|pdf`. Writing the CSV, drawing the PDF and encoding the weekly PNG run off the main thread (`withContext(IO/Default)` inside the now-`suspend` `Sharing` functions). `Sharing.shareImage` and both exports go through one private `shareFile` (FileProvider, `exports/` cache dir) so every share uses the same chooser.
- Export (`Sharing.exportCsv(context, expenses, categories, fileName)`) writes `CsvColumns.HEADER` = `date,title,category,payment_mode,amount,paid_by,group_id,note`. Since 1.5.0 `date` is ISO `yyyy-MM-dd` (earlier builds wrote the localised long label, which could not be read back); `category` is the display label.
- `data/repository/CsvImporter` parses with `Csv.parse` (quoted cells, `""` escapes, CRLF, BOM; a `"` only opens a quoted cell at the start of a cell, so `5" TV` stays literal), requires `date`, `title`, `amount`, and accepts ISO, `d/M/yyyy`, `d-M-yyyy`, and the pre-1.5 long label (`EEE, d MMM yyyy` / `d MMM yyyy`) in English, Hindi and Gujarati. Amounts may carry ₹/$/€ and grouping commas (`1,25,000`, `1,250.50`); a leading minus (`-` or `−`) marks a credit (exports write credits as negative amounts, so the round trip works); anything else (`1.234,50`, zero) is counted as unreadable rather than guessed. Titles and notes are title-cased like a normal save. Duplicates are detected against existing rows on `(epochDay, lower(title), amount, category)`. New rows go in with one `ExpenseDao.insertAll` (single transaction), bypassing `ExpenseRepository.save`, so no points or budget alerts fire; `BadgeTracker.refresh()` runs once at the end. `ProfileViewModel.importCsv` runs it on IO under `NonCancellable`. Custom category ids are `custom_<UUID>` (was `custom_<millis>`, which could collide when an import created several in one millisecond).
- `AppContainer.eraseAll()` cancels enabled reminder alarms, runs `db.clearAllTables()` and deletes the export cache on IO, cancels all notifications, clears DataStore last, then re-runs `bootstrap()`. Settings go last so an interrupted erase can never leave `onboarded = false` on top of the old database (onboarding would then just rename the old owner). `MainViewModel.eraseAll()` sets `erasing`, which holds the gate on Onboarding for the whole wipe so no screen reads a half-empty DB, and runs the erase under `NonCancellable` because the Profile screen's view model is destroyed as soon as the gate changes.

### Avatar & moods
Festival outfits (`Outfits.DIWALI_SILK`, `HOLI`, `GARBA`, `KITE`, `RAKHI`, `BAPPA`, `TIRANGA`, `SANTA`, `SEQUIN`) and accessories (`Accessories.GULAL`, `SANTA_HAT`, `PARTY_HAT`) are drawn in `drawBody`/`drawAccessory` like the others; patterned ones (zari border, Holi splashes, garba mirrors, tricolour bands, sequins, Santa belt) clip to the torso path.
`ui/components/AvatarView.kt` draws the character on a Canvas using a 100×100 coordinate space (`Pen` helper scales paths). The canvas is clipped to a circle with a themed `background`, so the bust is naturally cropped at the shoulders — never wrap it in another circle. Faces, hair and clothes use radial/vertical gradients for a soft 3D look; the outline is a faint 25% brown. `animated` enables breathing/gentle sway/blink, idle gestures and actions. Actions: pass `play = AvatarPlay(action, nonce)` (`domain.AvatarAction`: WAVE, JUMP, SPIN, DANCE, WINK, CHEER, LAUGH, each with its own `durationMs`); a new nonce replays. One `LaunchedEffect(animated, play, idleActions)` runs the requested action and then, when `idleActions = true` (Home and studio only), loops idle gestures (`IdleGestures`, every 9–15 s), so a new `play` cleanly cancels whatever was running — do not add a second effect that animates `progress`. `poseFor(action, t)` is evaluated inside the Canvas draw block (so actions only redraw, never recompose) and turns progress into a `Pose` (translate, rotation, scale, left/right arm raise, wink, laugh, burst), applied around the bottom-centre pivot; arms are drawn by `drawArm` from the shoulders, `drawBurst` paints the cheer confetti ring and the wink sparkle. `AvatarConfig.faceShape` selects the jaw curve in `facePath()` (the same path clips stubble and chin-strap beards); `AvatarConfig.beard` is drawn only for MALE (`drawBeard` before the mouth, the mustache after it). `AvatarConfig.gender` (from `members.gender`) widens the shoulders and drops the lashes for MALE, and `AvatarConfig.mood` is the mood saved from the studio (`members.mood`, null = automatic) — `AvatarView` defaults its `mood` parameter to it so every call site shows the saved mood, and the dashboard only computes a mood when none is saved. `mood` (`domain.Mood`, 10 values) maps to a private `Face` spec (`faceFor`) — brow tilt/raise/asymmetry, eye openness/scale, heart eyes, mouth shape and a floating extra (hearts, sparkles, sweat, tears, question mark, Zzz, steam). `moodFor(progress, hasBudget, streak, daysSinceLastLog, hour, dayOfMonth)` picks the mood in priority order angry → worried → sleepy → sad → confused → love → excited → smart → neutral → happy; the greeting is `moodLine(mood, today, name)` — a line from the mood's `linesRes` string-array chosen by epoch day, so it changes daily — prefixed by a time-of-day string.

### Gamification rules
All numeric rules live in `domain/Gamification.kt` (`PointsRules`, `Levels`) and `domain/Catalogs.kt` (`RewardCatalog`, `BadgeCatalog`). `GamificationRepository` is the only writer of points/badges/unlocks and emits `RewardEvent`s on a `SharedFlow`; `MainViewModel` turns those into the toast, confetti and reward notification.

- Streak logic: first log of a day increments the streak if the previous log was yesterday, otherwise resets to 1.
- Level = `floor(sqrt(lifetimeXP / 100)) + 1`; thresholds `(level-1)² · 100 → level² · 100`.
- Month-under-budget award is evaluated once per month in `BudgetMonitor.closePreviousMonthIfNeeded()` on app start, guarded by `profile.lastBudgetCheckMonth`.
- Free catalog items are inserted into `unlocks` at bootstrap, so "unlocked" is the single source of truth for both themes and avatar parts.
- **Badges** are not granted from individual `record…()` calls. `BadgeCatalog.progress(id, snapshot)` maps every badge to a number from a `BadgeSnapshot` (expense counts, hours of day, notes, voice logs, streak, groups, settlements, members, reminders, custom categories, paid unlocks by kind, months under budget, level, language). `BadgeTracker.refresh()` builds the snapshot from the DAOs and calls `GamificationRepository.checkBadges()`, which grants every badge whose progress reached its target (one ledger line + event each). Repositories call `badges.refresh()` after anything that can move a counter (expense, group, settlement, member, reminder, category, unlock, language) and `AppContainer.bootstrap()` runs it on start, so badges added in an update are awarded retroactively. `BadgeTracker.statuses` is the live `Flow<List<BadgeStatus>>` behind Rewards and the Badges page; `sortedForDisplay()` orders earned first, then by completion.
- **Re-splitting**: `GroupRepository.addMemberToAllGroups(memberId, resplitPast)` and `resplitWithout(memberId)` recompute `SplitCalculator.equalShares` for every EQUAL-split group expense (custom splits are left untouched) through `ExpenseDao.upsertWithSplits`, so balances update consistently.

### Household money & capture (engineering)
- `HouseholdDao` holds every new table; `HouseholdRepository` owns khata, services, gold and chits, and is the only place that turns a khata payment or service bill into an expense (`logExpense` → `ExpenseRepository.save`, so points, budget alerts and badges behave like a normal expense). Pure calculations live beside it as extensions: `ServiceEntity.qtyOn` / `monthBill` (days before `startEpochDay` or after today are not billed), `List<ShopEntryEntity>.khataBalance`, `GoldEntity.value(rate24k)`, `ChitEntity.paidAmount/completed/nextDueMonth`. `domain/Household.kt` has `ServiceBilling`, `ServicePresets`, `ServiceMonth`, `GoldKarats`. The 24K gold rate is the DataStore setting `goldRate24k`.
- Credits: there is no flag column — `ExpenseEntity.isCredit` is `amount < 0`. SQL `SUM(amount)` and every in-memory `sumOf { amount }` therefore net credits out. Readers that must only see spending filter explicitly: `BadgeTracker` (`spends`), `ExpenseRepository.save` (no points/budget alert for credits), Dashboard/Insights/weekly category and payer lists (`total > 0`), whose share bases are the sums of those positive lists (Insights `categoryTotal`/`modeTotal`/`payerTotal`, Dashboard donut centre), and `BudgetMonitor.closePreviousMonthIfNeeded` (`ExpenseDao.spendCount` > 0 and net ≤ budget). `Double.money()` renders negatives as `+₹50`, so every amount and net total shows credits the same way; `ExpenseRow` and the capture inbox colour them `CreditGreen`. Insights trend values and `budgetProgress` are clamped at zero. `ExpenseRepository.save` records the voice log for credits too. With credit on, `AddExpenseForm.groupId` is kept but ignored by `isValid` and dropped on save. `PaymentParser.Captured` carries a signed amount (negative = incoming), and `payment_drafts.amount` is signed the same way.
- Capture: `notifications/PaymentListener` (`src/full/java`; `NotificationListenerService`, declared in `src/full/AndroidManifest.xml` with `BIND_NOTIFICATION_LISTENER_SERVICE`) joins title + big text, and `CaptureRepository.capture()` keeps only packages in `PaymentParser.sources`, parses with `PaymentParser.parse` (amount after ₹/Rs/INR, a debit verb required, skip words win, payee after to/at/towards up to on/via/ref/…, VPA trimmed before `@`), de-duplicates against `payment_drafts` and `expenses.createdAt` in a 10-minute window, stores a `PaymentDraftEntity` and posts on the `capture` channel. `accept()` and the add form (`Routes.addExpense(draftId = …)`) both delete the draft after saving. Whether access is granted is read with `NotificationManagerCompat.getEnabledListenerPackages` on every `ON_RESUME` of the Capture screen. Adding a source = one line in `PaymentParser.sources`; tune wording with the regexes there.
- Reminder auto-log runs inside `ReminderReceiver` before rescheduling, so it works with the app closed. `HomeQuestApp.appScope` has a `CoroutineExceptionHandler` that logs instead of crashing, so a failure in a receiver or the notification listener can't take the process down.
- `PaymentListener` checks the package against `PaymentParser.sources` before reading any notification text; other apps' notifications are never inspected. `CaptureRepository.accept` deletes the draft before saving, so a double tap can't add it twice.
- `ui/components/MonthGrid` (locale-aware week start, one composable cell per day) is shared by the Calendar and the services tally; `PaymentModeRow` (in `AddExpenseScreen.kt`, next to `MemberChip`) is shared by the add form, khata and services.
- Dashboard: `DashboardState.budgetCrossDate` for the forecast, `pendingCaptures` from `CaptureRepository.drafts`, and `week: WeeklySummary` (built in the spend slice, streak/points filled in the final combine) rendered by `util/WeeklyCard`.

### Notifications
- Channels (one per sound, since Android fixes a channel's sound when it is created): `nudges` (high, boing), `bills` (high, doorbell), `auto_logged` (default, cha-ching), `budget_warning` (high, dun-dun), `over_budget` (high, boom), `badges` (default, power-up), `levels` (default, air horn), `streak_risk` (high, sad trombone), `streak_win` (default, fire), `captured_payments` (default, whoosh; full build only), and one `festival_<pack>` channel per festival pack in the *Festivals* channel group. They are declared by the private `Channel` enum in `NotificationHelper.kt`, whose `replaces` field names the 1.7 channel each one succeeds. `createChannels()` deletes the 1.7 channels (`reminders`, `budget`, `rewards`, `capture`) because their sound can't be changed; a 1.7 channel the user had switched off is recreated as switched off in each successor (importance NONE), so nobody's mutes come back after the update. A reminder with an amount posts on `bills`, without one on `nudges`.
- Sounds: `res/raw/sfx_*.ogg` (19 files, about 420 KB, original synthesised effects — no third-party audio). `notifications/Sounds.kt` has the `Sound` enum (raw id + `android.resource://` URI; `Sound.of(pack)` maps a festival pack to its sound) and `SoundPlayer`, a two-stream `SoundPool` held by `AppContainer.sounds`. It loads a sample on first use and plays it once loaded, skips playback unless the ringer is in normal mode, and is only called from the main thread (view-model scope). In-app sounds are gated by `AppSettings.soundEffectsEnabled`, and `MainViewModel` skips the in-app sound for a level-up, milestone or badge whose notification it has just posted (the channel already plays the same sound), so nothing plays twice.
- Reminders: `ReminderScheduler.schedule()` sets one `AlarmManager` alarm per reminder (`setExactAndAllowWhileIdle`, falling back to `setAndAllowWhileIdle` when exact alarms are not permitted on API 31–32) with a broadcast `PendingIntent` keyed by reminder id. `ReminderReceiver` posts the notification and reschedules (or disables a ONCE reminder); `BootReceiver` calls `ReminderRepository.rescheduleAll()` and `EngagementScheduler.scheduleAll()` on `BOOT_COMPLETED`, `TIME_SET` and `TIMEZONE_CHANGED`, and `AppContainer.bootstrap()` does the same on every cold start. Manifest: `SCHEDULE_EXACT_ALARM` (≤32), `USE_EXACT_ALARM` (33+), `RECEIVE_BOOT_COMPLETED`.
- Streak and festival alarms: `notifications/EngagementScheduler.kt` keeps two inexact `setAndAllowWhileIdle` alarms on `EngagementReceiver` (actions `STREAK_CHECK` daily at 21:30 and `FESTIVAL` at the next `FestivalCalendar.nextGreeting`); they are nudges, so they deliberately don't use exact alarms. The receiver posts `showStreakRisk` when `streakDays >= 2` and the last log was yesterday, or `showFestival` when today is the main day of the active festival, then schedules the next one. Both need `onboarded` and `engagementNotificationsEnabled`. Streak milestones (`RewardEvent.StreakMilestone`) post `showStreakMilestone` from `MainViewModel`.
- Copy: `NotificationHelper` resolves strings through `LocaleHelper.localized(context, settings.language)`, so wording follows the in-app language. Titles and bodies come from `notif_*` string arrays via `Resources.rotate(array, seed)` with `seed = epochDay + something stable` (reminder id, label hash, badge id hash, level, streak). Title and body use the same seed against arrays of coprime length, so the pair only repeats after length × length days (nudges 20 × 31 = 620 days, streak risk 7 × 9, streak milestones 5 × 6). Keep each pair coprime when adding lines, and every placeholder set identical across languages. Festival greetings use the festival's `titleRes` (with the member's name) and `lineRes`.
- Budget alerts fire from `BudgetMonitor.afterExpenseAdded()` when a total crosses 80% (`budget_warning`) or 100% (`over_budget`) of a limit.
- `POST_NOTIFICATIONS` is requested once on launch (API 33+). `NotificationHelper.canPost()` guards every post.

### Festivals & celebrations (engineering)
- `domain/Festivals.kt`: `FestivalPack` (name, emoji, theme id; 9 packs), `Festival` (name, title and line strings, pack, greeting time; 10 occasions), `FestivalDay` (start, main, end; `key` = `NAME:yyyy-MM-dd`) and `FestivalCalendar` (`occurrences(year)`, `active(date)`, `upcoming(date, 7)`, `nextGreeting(now)`). Lunar dates live in one table for 2026–2030; after that only the fixed-date festivals occur until the table is extended. New Year's window starts on 31 Dec of the previous year, so `active` checks this year and next.
- `AppContainer.festival` is `Dates.days().map(FestivalCalendar::active)`, so it changes at midnight. Pack items are `RewardItem`s with `pack` set and cost 0; `RewardCatalog.defaults()` excludes them, `GamificationRepository.redeem()` refuses them, and only `claimPack(pack)` unlocks them — the shop and studio call it only when the pack is the active one. Because their cost is 0 they never count toward the paid-unlock badges. `RewardCatalog.dressFor(pack, config)` swaps in the pack's outfit and accessory.
- Theme: `AppSettings.themeFor(festival)` returns the pack theme when `festiveMode` is on and `festiveThemeSkipped` isn't this festival's key; `MainActivity` and `RewardsViewModel.activeThemeId` both use it. Applying another theme in Rewards during a festival writes `festiveThemeSkipped`.
- Celebrations: `ui/components/Celebrations.kt` has `Celebration` (`Streak`, `Level`, `Holiday`), `CelebrationHost` and a full-screen `Dialog`; `MainViewModel.celebrations` is a queue so a level-up and a milestone from the same expense show one after the other. The festival celebration is queued whenever Festive mode is on and the active festival's key differs from `festivalSeen`; dismissing sets it, and the Home banner clears it to replay. *Claim* goes through `AppContainer.claimFestival(day)` — also used by the shop and studio claim buttons — which, under a `Mutex`, unlocks the pack and awards `PointsRules.FESTIVAL_GIFT` (ledger `festival:<NAME>`) only if `festivalGifted` isn't this key yet; the modal then dresses the active member. A celebration is removed from the queue before any work starts, so a double tap can't act twice. Level-ups and milestones no longer go to `RewardToast`.
- Effects: `ui/components/FestiveEffect.kt` draws looping particle effects on a `Canvas` from one 12-second infinite clock (`EffectStyle`: fireworks, powder, snow, kites, confetti, petals, lights; `FestivalPack.look()` picks style and colours) and the animated `StreakFlame`. Every motion uses whole cycles of the clock, so loops are seamless.
- Streaks: `ProfileEntity.currentStreak(today)` (in `GamificationRepository.kt`) is 0 when the last log is older than yesterday; display code uses it, while `BadgeTracker` keeps the stored `streakDays` (best run so far counts toward badges). `StreakMilestones.days` lists the milestone days, `reached(streak)` also counts every 100 days after 365, and `next(streak)` gives the next one.
- Settings added in 1.8 (DataStore): `engagement_notifications`, `sound_effects`, `festive_mode` (all default true), `festival_seen`, `festival_gifted`, `festive_theme_skipped`.
- **Adding a festival**: add a `Festival` entry (and a `FestivalPack` with a `ThemeIds` constant, a `Palette`, `RewardItem`s, an outfit branch in `AvatarView`, a `Sound` + `res/raw` file and a `look()` entry if it needs a new pack), its dates in `FestivalCalendar` (fixed list or the lunar table), and `fest_<x>`, `fest_<x>_title`, `fest_<x>_line` strings in all three languages.

### Design system
`ui/components/DesignSystem.kt` holds the shared building blocks: `HqCard` (22dp radius, `surfaceContainerLowest`, hairline border), `SectionCard`, `StatTile` (label, value, a Material icon in an accent-tinted tile, hint), `LevelProgress` (labelled XP bar), `TopBarAction` (44dp tinted rounded-tile top-bar button with button semantics), `ProCard` (gold Pro upsell), `PickerRow` (icon tile + label/value + chevron, the row style of the add-transaction form), `HqTextField` (label above the box, soft filled container, border only on focus/error, sentence capitalisation by default), `PrimaryButton`, `TimeWheel` (three snap-scrolling `LazyColumn` wheels with a highlighted centre row and fade overlays; the centre item is derived from `layoutInfo`), and the PIN components (`PinDots`, `PinPad`, `PinEntry`, `PinSetupSheet`). `OptionSheet`, `CategoryGrid`, `MemberChip` and `MemberFlow` live in `AddExpenseScreen.kt` and are reused by the group, family, reminder and category sheets. All `Text` that can grow is given `maxLines` + `TextOverflow.Ellipsis`. New screens should compose these rather than raw Material `Card`/`OutlinedTextField`.

### Session & navigation
`MainActivity` switches between `OnboardingScreen`, `LockScreen` and `HomeQuestNavHost` via `MainViewModel.gate()`. `MainViewModel.settings` is `null` until DataStore has loaded and `MainActivity` renders nothing until then, with a `Crossfade` between gates — rendering the default settings first flashed Onboarding/Lock for a frame on launch and sign-out (1.3.x flicker). The `NavHostController` is created inside `HomeQuestNavHost`, so each unlock gets a fresh controller — reusing one across the lock screen caused the "ViewModelStore should be set before setGraph" crash seen in 1.1. Sign-out goes through `MainViewModel.signOut()` (clears `sessionUnlocked` and `activeMemberId`).

`MainViewModel.signOut()` writes `activeMemberId = 0` and waits for the settings flow to show it before clearing `sessionUnlocked`. Clearing it first (≤1.4) briefly produced LOCKED with the old member preselected; with App lock on and a PIN-less member that member was auto-unlocked again, so Log out appeared to do nothing after switching profiles. `LockScreen` only preselects a member when `preselectedId` matches one (app-lock re-prompt); after sign-out `activeMemberId` is 0 so the picker is always shown — auto-selecting a lone PIN-less profile was what made Log out appear to do nothing in 1.2.

Bottom tabs (`HqBottomBar`): Home, Expenses, Groups, Me plus a centre FAB that opens `Routes.addExpense()`; Rewards is a normal pushed route reachable from the Home pill and Me. The Home tab calls `popBackStack(Routes.DASHBOARD, inclusive = false)` instead of `navigate` — Dashboard is the graph's start destination and re-navigating to it with `restoreState` could leave the tab unresponsive after visiting other tabs. The other tabs `navigate` with `popUpTo(Routes.DASHBOARD) { saveState = true }`. The outer `Scaffold` in `HomeQuestNavHost` uses `contentWindowInsets = WindowInsets.navigationBars`: the status-bar inset is left to each screen (its `TopAppBar`, or `statusBarsPadding()` on Home and Me). Until 1.6.0 the outer scaffold also applied the status-bar inset, which doubled the gap above every top bar. Every screen-level `Scaffold` passes `contentWindowInsets = WindowInsets(0, 0, 0, 0)`, otherwise the navigation-bar inset is applied twice and a blank band appears above the bottom bar. The bar reserves `FabOverhang` (30dp) above itself for the raised add button. The NavHost's bottom padding subtracts that overhang while the bar is shown, so content scrolls under the transparent strip. Tab lists therefore keep about 40dp of bottom content padding. `NotchedBarShape` is the rounded bar minus a circle of `FabSize / 2 + 6dp` at the top centre (`Path.combine(Difference)`). Concave outlines only cast shadows from Android 10, so on API 26–28 the bar falls back to the plain rounded-top shape.

Routes with arguments: `Routes.rewards(pro)` (`rewards?pro=` — `true` opens the Pro plans sheet on arrival; the sheet's open state is `rememberSaveable`), `Routes.CALENDAR`.

### Launcher icon
`res/mipmap-anydpi-v26/ic_launcher.xml` (and `_round`) is an adaptive icon: `drawable/ic_launcher_background.xml` (gradient + soft circles), `drawable/ic_launcher_foreground.xml` (house, door, window, star coin, drawn small enough to sit inside the 33-radius safe circle so no launcher mask clips it — 1.4.0 shrank it after the 1.3.1 version was cut at the edges) and `drawable/ic_launcher_monochrome.xml` for themed icons. `drawable/ic_notification.xml` is the matching white-house silhouette used for all notifications. Source SVG of the design is reproduced in the foreground drawable paths.

### Theming
`Palettes.forId(themeId)` returns a `Palette`; `Theme.kt` builds light/dark `ColorScheme`s and animates primary/secondary/tertiary/background/surface/containers when the theme id changes so unlocking a theme visibly morphs the UI. A palette with `glass = true` (Glass) goes through `ColorScheme.glassy(dark)`. That makes `background`/`surface` transparent and `surfaceContainerLowest`, `surfaceContainerHigh`, `surfaceVariant` and `outlineVariant` translucent white, so cards, fields and the bottom bar frost. Sheet, menu and dialog containers (`surfaceContainer`, `surfaceContainerLow`, `surfaceContainerHigh`, `surfaceContainerHighest`) stay 94–96% opaque, because dialogs open in their own window without the backdrop and would otherwise be see-through. Chart point markers use `onPrimary` rather than `surface`, which is transparent under Glass. `HomeQuestTheme` then wraps content in `GlassBackdrop` (the base colour plus three radial glows in primary, tertiary and secondary). Anything that paints `colorScheme.background` as a solid fill shows the backdrop under Glass, which is intended. `MainActivity` passes `settings.themeFor(festival)` rather than `settings.themeId`, so festival themes (Diwali, Holi, Garba, Kites, Rakhi, Bappa, Tiranga, Christmas and the glass New Year) take over during their window when Festive mode is on.

### Localisation
All user-facing text is in `res/values/strings.xml` (English, the source of truth), `values-hi` and `values-gu`; every key exists in all three and placeholder sets are identical. Enums/catalogs carry `@StringRes` ids (`Mood`, `PaymentMode`, `RepeatRule`, `RewardKind`, `Relations`, `RewardItem`, `Badge`, `LevelInfo`). The language is a DataStore setting; `MainActivity` wraps the whole tree in `CompositionLocalProvider(LocalContext provides LocaleHelper.localized(...), LocalConfiguration ...)`. `LocaleHelper.localized` returns a `ContextWrapper` around the Activity whose `getResources()` is the localised one — it must stay a wrapper of the Activity, because `rememberLauncherForActivityResult` finds its `ActivityResultRegistryOwner` by walking `LocalContext` up to the Activity (a bare `createConfigurationContext` result crashed the add-expense and voice screens in 1.3.0) and sets `Locale.setDefault`, so `stringResource`, `java.time` formatters and the speech recogniser all follow it without an Activity restart. Relation values are stored as lowercase keys (`me`, `partner`…) and resolved with `relationLabel()`; rows written by older versions (`Me`, `Partner`) still match case-insensitively.

### Voice entry
`AddExpenseScreen` launches `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` (no RECORD_AUDIO permission needed; the system recogniser handles it) in the app language and feeds the first result to `VoiceParser.parse(text, customCategories)`, which extracts the first number as the amount, matches payment-mode and category keyword lists (English plus common Hindi/Gujarati words) and custom category names, strips filler words and title-cases the rest. A `note`/`नोट`/`નોંધ`/`નોટ` marker splits the sentence: text after it becomes `Result.note` and is excluded from parsing. `AddExpenseViewModel.applyVoice` sets the note to that part, or to the whole transcript when no marker was said and the note is still empty. The result pre-fills the form for review; nothing is saved automatically.

### Adding things
- **New built-in category**: add a constant and `Seed` to `BuiltInCategories` (plus `cat_*` strings in all three languages); `ensureDefaults()` inserts it on next start. Custom categories need no code.
- **New reward**: add a `RewardItem` to `RewardCatalog.items` with a constant in `Models.kt`. Outfits/hair/accessories also need a drawing branch in `AvatarView.kt`; themes need a `Palette`.
- **New badge**: add a constant and `Badge` to `BadgeCatalog.badges` (tier, `target`, `unitRes`, `howTo` steps; strings `b_<id>`, `b_<id>_d`, `b_<id>_1..3` in all three languages) and a branch in `BadgeCatalog.progress()`. If it needs a new counter, add it to `BadgeSnapshot` and `BadgeTracker.build()`. Nothing else changes — it is awarded on the next `refresh()`.
- **Tappable shapes**: put `.clip(shape)` before `.clickable` (or pass the shape to the background after a clip) so the ripple follows the shape; `HqCard` clips to `CardShape` when it has `onClick`. Unclipped clickables showed square ripples on round buttons until 1.5.0.
- **Anything that depends on "today"**: collect `Dates.days()` and `flatMapLatest` over it (see `DashboardViewModel`, `ExpensesViewModel`, `BudgetsViewModel`, `InsightsViewModel`) instead of capturing `LocalDate.now()` in a constructor — that is what showed October totals under "Spent in November" at midnight.
- **New screen**: add a route in `Routes`, a `composable` in `HomeQuestNavHost`, and a `ui/screens/<feature>` package.

### Known limits / next steps
- Local-only; no sync, auth or multi-device sharing (group sharing is via text summary). Giving a member access from another phone needs a backend (e.g. Firebase phone auth + Firestore) — a separate project.
- Expenses store a single currency symbol globally; no FX.
- Voice parsing is keyword based; amounts spoken as words ("two hundred") are not recognised.
- Auto-capture reads notifications, so it only sees payments made while this phone shows the alert, and a bank or app that words its alert differently is missed until its phrase is added to `PaymentParser`. A per-sender test set from real notifications is the next improvement. In India, Play Protect's enhanced fraud protection blocks sideloaded installs (browser, messaging app, file manager) of any APK declaring a notification listener or SMS permissions — hence the `lite` flavour; `READ_SMS` would hit the same block; on the Play Store it is a restricted permission that needs a permissions-declaration approval (SMS-based money management is one of the allowed exception categories). The regulated alternative for bank data is the RBI Account Aggregator framework, which needs a licensed AA partner and a backend. None of these apps offer a public transaction API.
- UPI top-up is trust-based: `util/Upi.kt` builds the deep link (private `ID`, amount, note) and parses the optional `response` extra, but there is no way to prove a payment happened without a payment gateway (Razorpay, Cashfree, PhonePe PG) and server-side verification. Treat it as a demo, not a store. The manifest declares a `<queries>` entry for the `upi` scheme so the chooser can see UPI apps on Android 11+.
- No unit tests yet; `SplitCalculator`, `Levels` and `GamificationRepository` are the first candidates.
